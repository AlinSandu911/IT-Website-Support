# Coast Turtle's IT Land website

## How it fits together

- **Pages** are the `*.html` files in this folder. The menu, footer and phone action bar live once in `partials/` (`header.html`, `footer.html`, `mobile-bar.html`); the server slots them into any page containing `<!-- include: header -->` and so on. Change the menu or footer there, not in each page.
- **Styles** come from `css/site.css`, generated by Tailwind from `src/styles.css` and the colour theme in `tailwind.config.js`.
- **The server** (`server.js`) serves the pages, saves requests and reviews, and emails you about new requests.
- **Hosting** is Render, which redeploys automatically when changes are pushed to GitHub.

## Local development

1. Install Node.js 22.
2. Copy `.env.example` to `.env` and fill it in (all values are optional locally).
3. In this folder run:

   ```powershell
   npm install
   npm start
   ```

4. Open `http://localhost:3000`. Pages must be opened through the server (not by double-clicking the file), or the shared header and footer won't appear and forms won't send.

After adding or changing classes in any page, partial or script, rebuild the stylesheet and commit `css/site.css`:

```powershell
npm run build:css
```

## Settings (Render > Environment)

| Setting | What it's for |
|---|---|
| `ADMIN_API_KEY` | The password for `admin.html`. Choose a long random value. |
| `RESEND_API_KEY` | Sends email notifications through Resend (free; account created with `antoniosandu21@gmail.com`). Render blocks normal email (SMTP), so Resend is used instead. |
| `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN` | The free Turso online database where requests and reviews are stored. Without them the server uses a local `database.db` file, which Render wipes on every deploy. |

`GET /api/health` shows whether the server is using Turso. Use **Send test email** on `admin.html` to check email delivery.

## Requests, reviews and the admin page

- Customers use the single form on `contact.html` (`#request`) to request a repair or quote; the preferred day and time are optional. The old `booking.html` address redirects there.
- Reviews are saved unpublished and only appear on the site after you publish them.
- `admin.html` lists requests (set their status: new / confirmed / completed / cancelled), lets you publish or hide reviews, export requests as CSV, and send a test email. Keep the admin key private.
- If the server can't be reached, the contact form falls back to Web3Forms (key in `js/main.js`; reviews use it too, in `js/reviews.js`), then to an email draft.

## Security notes

- Only website files (`*.html`, `css/`, `js/`, `images/`, `favicon.ico`, `robots.txt`, `sitemap.xml`) are public; the server blocks everything else, including `partials/`, `src/` and any database file. Put new public files in those folders.
- Form endpoints are limited to 10 submissions per visitor per 15 minutes.
- Never commit `.env`.

## Site address

The full address `https://it-website-support.onrender.com` appears in `sitemap.xml`, `robots.txt`, each page's preview tags (`og:` and canonical links) and the structured data in `index.html`. Update all of them if you move to your own domain.

`privacy.html` and `terms.html` are starter policies; review them if your business setup changes.
